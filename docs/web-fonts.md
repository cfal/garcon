# Web font optimization

The five optional UI/editor font faces are generated by hand and committed. Normal builds consume the WOFF2 files and CSS directly; they do not install Python, download source fonts, or run font processing. Public CSS family names, `font-display: swap`, fallback stacks, optical sizing, and default/system typography are preserved.

None of these originals has embedded glyph hint instructions. Browser auto-hinting still affects rendering; removing reference cmap entries can change it. ## Usage and fidelity budget

[Usage audit](../scripts/fonts/usage.json) records stylesheets, Svelte classes and inline `style:font-family` directives, CSS shorthands, and editor/terminal-generated styles. It includes source/message character inventories. The important exceptions to a simple 400/700 budget are tickets' 550 and 620 weights, the TypographyPreview component's independent inline family, editor bold/italic syntax styles, bold inside italic Markdown, and strong headings reaching 900. There are no explicit optical-sizing overrides, so Inter retains its entire automatic opsz 14–32 range. JetBrains retains wght 400–800; Inter retains 400–900. No variable axis is pinned to a single value.

The retained feature allowlist is `calt ccmp clig curs kern liga locl mark mkmk rlig rclt tnum`, intersected with each source's actual tables. It preserves default shaping/positioning and the explicitly used tabular numbers in tickets, usage, and file search. Unselected stylistic sets, character variants, small caps, fractions, superscripts/subscripts, and other opt-in alternates are removed. The inventories list every original and remaining feature by table.

Garcon displays arbitrary chat, file, diagram, and terminal text. A scan of repository strings cannot bound that content. All existing cmap coverage is retained, including Latin-1, Latin Extended-A, Greek, Cyrillic, symbols and supported combining marks. Unsupported characters retain their previous system fallback. None of the five originals covers CJK, and no CJK font is introduced.

Core seeds are ASCII, NBSP, U+2010/U+2011, curly quotation marks, en/em dashes, ellipsis, current English UI messages, and common keyboard symbols. No current stylesheet enables `hyphens: auto`; U+2010 is nevertheless reserved for browser-generated hyphens. Every character connected to the seed by an active kerning/mark positioning lookup stays in the core. Supported combining marks are duplicated in both files, and the extended face is declared first so the core wins ordinary overlapping clusters. This makes Inter's core large: splitting a shaping run at a face boundary changes kerning and combining-mark placement even when each face contains the right glyphs. The CSS ranges overlap only for supported combining marks, and every advertised code point exists in its file. Inter extended files also retain hidden ASCII reference cmap entries/glyphs used by FreeType stem-width and blue-zone calculations. Those support entries stay outside the extended CSS range, preserving auto-hinting without advertising ASCII to the extended face. The inventory records advertised ranges and hidden support separately. There is no generated fallback face between them.

The generator preserves original positive-weight `glyf`/`gvar` data and removes only tuples confined to the unused negative half of the weight axis. Generic FontTools axis instancing rounds inferred IUP deltas, shifting JetBrains' 0/8 outlines by half a font unit. The manual check compares every mapped output outline and advance against its source at boundary/fractional weights and both Inter optical-size endpoints, in addition to the browser pixel matrix.

## Loading

The original application has no font preloads. The new head preloads one normal core per distinct bundled family selected in typography preferences. System/default selections preload nothing. Italic cores and all extended files load on demand. Vite's `no-inline` asset query preserves real files even for tiny subsets. Relative asset imports remain valid at runtime base paths.

Previously the service worker eagerly cached all emitted font formats, defeating font preference and unicode-range savings. It now caches fonts after a real request through the active worker. Those cached fonts remain available offline; a face never requested through the worker may use its existing fallback offline. This change is necessary for conditional downloads. Embedding core fonts in CSS and idle precaching extended fonts remain separate future work.

The real-worker probe verifies an empty font cache after installation, one Inter core after ASCII/quotes/accents, and the extended Inter face only after adding ∑. [Cache observations](font-optimization/cache.json).

## Specialized fonts retained

[Specialized inventory](../scripts/fonts/inventory-specialized.json) also audits every KaTeX WOFF2 and both pinned external Monaspace Nerd Font faces. These resources are unchanged, rather than claiming an unverified rendering-preserving optimization:

- KaTeX: 20 WOFF2 files, **259,792 bytes**, with no variable axes or GSUB/GPOS features. Most contain real TrueType hint programs. Its lazy math renderer, glyph composition, and dependency-owned CSS retain all math coverage. The build also emits **303,116 bytes WOFF** and **513,664 bytes TTF** for older format fallbacks. One 3,624-byte WOFF2 is inlined in the lazy KaTeX CSS; the other 256,168 WOFF2 bytes have file URLs. These are alternative formats, not three downloads per glyph.
- Monaspace Neon NF: regular **1,260,028 bytes**, bold **1,275,000 bytes**, **2,535,028 bytes** together; 12,752 glyphs per face, static 400/700. Its existing terminal loader explicitly loads/registers both faces together and retains Nerd Font private-use fallback. Converting it to lazy split faces would change that activation/failure contract. No terminal loader, fallback, hinting, or font-display changes are included.

These 22 specialized faces are audited but not split or optimized in this change. Their retained byte cost is explicit above; the savings below apply to the five application-owned bundled faces. Math/terminal-specific subsetting needs its own exhaustive rendering and activation proof before replacing them.

## Regeneration

Run from the repository root with Python 3.12+ after installing the locked Bun dependencies (3.13 is shown):

```sh
python3.13 -m venv /tmp/garcon-font-tools
/tmp/garcon-font-tools/bin/pip install -r scripts/fonts/requirements.txt
/tmp/garcon-font-tools/bin/python scripts/fonts/subset.py
/tmp/garcon-font-tools/bin/python scripts/fonts/check.py
/tmp/garcon-font-tools/bin/python scripts/fonts/audit.py
```

Python 3.13 and the pinned requirements were used for these outputs. `uv venv --python 3.13 /tmp/garcon-font-tools` and `uv pip install --python /tmp/garcon-font-tools/bin/python -r scripts/fonts/requirements.txt` are equivalent setup commands. Source WOFF2 downloads are hash-verified and ignored by Git; generated assets, CSS, reports and licenses are committed. Regular tests consume committed subsets and do not require this source cache.

Rerun and review the usage audit when changing source versions, UI/localized characters, inline/component/editor font settings, weights, features, optical sizing, or the supported typography range. New content alone does not require regeneration because existing source coverage is preserved. Adding an activated OpenType feature requires changing the allowlist and rechecking shaping boundaries, not just rerunning the generator.

After regeneration, build and capture the same-content oracle:

```sh
bun run build
bun integration-tests/scripts/font-matrix.ts /projects/font-proof/matrix
/tmp/garcon-font-tools/bin/python scripts/fonts/pixel-diff.py /projects/font-proof/matrix
bun integration-tests/scripts/font-proof.ts /projects/font-proof/application
/tmp/garcon-font-tools/bin/python scripts/fonts/pixel-diff.py /projects/font-proof/application
bun integration-tests/scripts/font-cache-proof.ts /projects/font-proof/cache
```

The scripts use isolated authenticated synthetic fixtures and new random ports. The application oracle uses one production build and identical synthetic content: before/control replace only bundled font-face rules with the full original sources and remove new preloads; after uses the real generated assets. Original read state and asynchronously loaded model labels settle before capture. This isolates the font change without introducing different application content. Service workers are blocked for per-page byte measurements and tested separately by the cache probe. Bytes are compressed font response bodies, excluding HTTP headers and unchanged application JS/CSS.

`pixel-diff.py` uses exact RGB comparisons with no tolerance or masks. It writes before/after difference images and independent original-font control differences. Different-sized rejected candidates are padded with white only to visualize/count the difference; actual dimensions are recorded and the check still fails. Any nonzero result exits with failure and must be inspected and explained; it is never silently blessed.

## Rejected smaller candidates and deliberate deviations

[Rejected-option measurements](font-optimization/rejected-options.json) use the same 720-row typography matrix. No candidate below is shipped. These are archived experiments against an earlier 769,172-byte candidate and its original matrix text, not deltas against the final artifacts. The candidate later failed the expanded accent cases and is not shipped; the figures quantify why those more aggressive options remain rejected.

| Candidate | Extra combined saving | Core saving | Rendering change |
| --- | ---: | ---: | --- |
| ASCII/UI-only core without positioning/combining closure | 15,064 bytes | 393,084 bytes | 2,850,163 changed pixels across the three families: kerning, mark placement and face-boundary shaping |
| Remove JetBrains rasterization controls | 104 bytes | **172 bytes larger** | 829,842 changed JetBrains pixels: different rasterization |
| Restrict Inter to 400–800 | 14,568 bytes | 9,684 bytes | 487,875 changed Inter pixels, including a 53px narrower widest row; removes used 900 and alters fractional-weight interpolation. The other 127 changed pixels in this experiment are the generic instancer's separately fixed JetBrains digit rounding. |

The kept core is larger than the requested small ASCII split because preserving shaping takes precedence. All existing characters are retained instead of a fixed Latin/content-only budget because user content is unbounded; extended files cost nothing on pages that do not need them. Glyph hinting is absent in the five original UI faces; the 30 bytes of source JetBrains raster-control tables are deliberately kept. Specialized math/terminal fonts remain untouched at the byte costs above. These are explicit deviations from minimizing/splitting every font; they preserve existing rendering or activation behavior.

A second matrix-exact candidate moved all letters/numbers into the core: **796,636 combined bytes**, but **594,236 core bytes**. The shipped split has 53,752 more bytes across all ten files, and saves **77,588 bytes across the preloaded/ordinary cores**. This favors the requested small initial download. A reduced hidden-reference experiment (`oOHfpx`) saved another **27,336 bytes** and matched the sampled Inter matrix; it is not enabled because it replaces the original complete auto-hinter reference set without proving equivalent metrics for arbitrary sizes/content.

## Pixel comparisons

The expanded font-only matrix compares **720 typography samples per revision**, totaling **53,356,464 pixels**: **zero changed pixels** and identical image dimensions. It covers normal/italic, 15 sizes from 9–36px, weights 400/500/550/600/620/700/800/900, tabular digits, code/ligatures, kerning, Latin accents, uncommon accented ligatures/bases, stacked marks, U+2010, Greek, Cyrillic and CJK. [Matrix results](font-optimization/matrix-pixels.json).

The real application has **48 before/after pairs plus 48 independent original-font controls** (144 captures), at 1440×1000 and 390×1000. All visible text is identical across each before/after/control triple. Of **43,920,000 compared page pixels**, **40 pairs are exact**; eight pairs contain **204 changed pixels**, all outside text. Every image has unchanged dimensions. The raw diff command deliberately exits nonzero for these differences; no tolerance, masking, or content substitution hides them. [Every pair and its classification](font-optimization/application-pixels.json).

| Difference | Pairs | Changed pixels | Explanation |
| --- | ---: | ---: | --- |
| Desktop rounded composer border | 5 | 198 | Channel deltas 1–2 at x332–348, y887–992 (y897 for two System scenes). Same border noise occurs in the original-font controls, including System scenes where no bundled font loads. Harmless browser edge/compositing rounding; no text/layout change. |
| Mobile editor reload SVG edge | 3 | 6 | Two pixels per bundled preference at x261, y16/18; maximum channel delta 11. Magnified inspection locates both pixels on the unchanged non-text SVG stroke. Harmless edge rasterization rounding; no text/layout change. |
| Content differences | 0 | 0 | Every before/after/control body-text snapshot matches. |
| Font rendering regressions | 0 | 0 | All changed page pixels are outside text; the font-only matrix is exact. |

Original-versus-original controls independently contain **435 changed pixels**, all on composer edges. The controls distinguish browser compositing noise from text changes; they are not subtracted from the reported before/after count. Earlier changing unread badges/model labels were removed from the workload by waiting for identical content, not by masking pixels.

Representative exact pairs are committed for durable inspection: [desktop before](font-optimization/desktop-before.png), [desktop after](font-optimization/desktop-after.png), [desktop diff](font-optimization/desktop-diff.png), [mobile before](font-optimization/mobile-before.png), [mobile after](font-optimization/mobile-after.png), [mobile diff](font-optimization/mobile-diff.png). The desktop scene includes accents, code, italics and bold inside italics; mobile includes CJK/system fallback. The complete scene set also includes the independently styled typography dialog and editor.

## Check scope

The production build, lint/type checks, isolated server startup, generated-file checks, real service-worker probe, and existing editor/Mermaid Chromium checks pass. `bun run test` was run and stops at the Codex history API compatibility test's unchanged five-second timeout. Two ScrollArea lifecycle cleanup tests also fail in the broader web run. Both failures were reproduced in a detached checkout of the untouched baseline; they are not repaired as part of font work. The broader suite is therefore not reported as green.

Pixel evidence is Chromium on Linux at device scale 1. It proves the captured scenes and tested typography combinations; it does not establish pixel identity on every operating system/browser/rasterizer or for every arbitrary future text/feature combination. The retained outlines, source coverage, automatic optical sizing, and rasterization controls reduce that remaining risk without changing fallback policy.
