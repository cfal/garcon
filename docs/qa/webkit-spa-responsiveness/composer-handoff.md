# Warm composer handoff in 12 visible panes

**Keep only the Source visibility guard.** On local WebKitGTK 2.50.6, stock ran a full textarea fit while the shared composer was inert on all 8 observed Source transfers, then fit it again when visible. Both production-built candidates removed all 8 hidden fits and retained all 8 visible fits. Source spacer writes and scroll events remained confined to the old and new feeds. Same-owner clicks did not write any spacer or measure the host. This demonstrates avoided work, not a consistent latency win or an iPhone/presentation measurement.

For nonempty Formatted inputs, the taller draft legitimately measured 258 px as an editable Source fallback and then 222 px after parsing; all three builds retained this change. Old reserves cleared and the ten uninvolved feeds had zero observed spacer writes or scrolls. Some rAF samples had no bound owner and both spacers zero; this by itself is not a mistaken publication or proof of a painted blank frame. The product changes neither host publication nor rich mounting.

**Behavior and exclusions.** The paired stock and `editor` runs passed all four draft/mode conditions, including clicked-feed focus, explicit composer focus, rapid A/B/A with a third chat receiving a synthetic turn, and trusted text insertion or selection replacement followed by a draft roundtrip. The `host` run passed all geometry, focus and rapid/background checks and three of four typing checks. The final varied Formatted guard timed out before the draft roundtrip; it combined ready text/owner, trusted input, focus and caret checks without logging which failed. In an isolated retry, the selection at keydown and beforeinput was [2,7] in one 22-character text node; the correct new text was in one 18-character node with collapsed local **and logical** caret [3,3]. Focus and roundtrip also passed. This does not explain or erase the first failure. There was no real IME or physical-device test.

Three preliminary runs were excluded: an invalid synthetic partition prefix stopped before browser startup; the first layout left no clickable reading area in the smaller pane at the tall-draft warmup; a first-ready-only check observed the real 222 px editor before ResizeObserver updated its preceding 258 px inset. The final comparisons use equally tall panes and check settled geometry after three consecutive ready samples.

## Reproduction

1. Build from each revision's root with `bun run build`. Use the checked-in [fixture setup and layout seeding](../../../integration-tests/scripts/pane-fullscreen.ts) and [GTK driver](../../../integration-tests/scripts/pane-benchmark-driver.ts), **not** the fullscreen gesture. Require a current build, use one exclusive local MiniBrowser session at 1840×960 inner, and create 12 fresh direct fake-provider chats with one completed turn and 28 synthetic short paragraphs each. Split at 50%, alternating horizontal and vertical: make four columns of two panes, then halve the four right-side panes vertically. Pick the first two equal-height 380 px-wide left-side panes with visible sidebar rows. Keep refs to all 12 native feed viewports.
2. For each fresh document, seed the fixture origin on its neutral `/robots.txt` as in the shared runner. Choose `composerInputMode` = `source` or `formatted`; use either two empty drafts or a 22-character ASCII line and four short paragraphs separated by blank lines. Wait for all feeds, the correct editable and the selected pane. Do not use private chat data. Use native pointer actions on unobstructed transcript text (`pane`) and the main chat button in `[data-sidebar-virtual-row]` (`nav`).
3. Per intent discard one moving and one same-owner click; take three of each, alternating order. Use the trusted pointerdown/click and nested rAF pattern in [record-interaction.js](record-interaction.js); for sidebar clicks match the row button instead of the viewport. `*_two_ms` is median pointerdown to the second callback requested by click. `*_ready_ms` is first sampled correct current pane, route, anchor, non-inert layer and editor/draft; same-owner readiness can precede click. Check final host height against its spacer within 0.6 px, all other spacers zero, original feed nodes intact and focus correct. Host diagnostic blocks report no timings.
4. **Separately** observe two same-owner clicks and one move each direction. Count native `getClientRects` and `scrollHeight` on the shared Source element, recording layer inertness and whether it had a box. Wrap the existing host `getBoundingClientRect` to log its returned height and presence/visibility of both editors, without adding layout reads. Observe `style` on all `[data-conversation-panel-composer-spacer]` and scroll events on the 12 viewports. Remove probes before validation reads. In the [CSV](composer-handoff.csv) the operation counts are totals, not timings; `blank_host_reads` means hidden Source without a ready rich editor, `overlap_host_reads` means visible Source and an empty rich container. `typing_roundtrip` is one check per document, repeated on its two intent rows.
5. Outside timing, issue two consecutive native pane clicks A→B→A while sending a fresh turn to a third chat; require the new message in that never-selected feed and the correct A draft. Explicitly select A, place a real DOM selection at [2,7] in the short draft (or [0,0] when empty), send one trusted W3C text key, check exact text, focused editor and collapsed caret, then switch away and back to verify draft isolation. Record only lengths, offsets, operation counts and timings. Dispose the WebDriver session and fixture in `finally`.
