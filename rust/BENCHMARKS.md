# Benchmarks

The TypeScript original compared with the Rust front door, with its native units on and with every request sent to the original. Generated by `bun rust/parity/bench.ts`; see [README](README.md).

## Method

- Machine: Intel(R) Xeon(R) CPU E3-1270 v6 @ 3.80GHz, 8 cores, Linux 6.8.0-142-generic. Bun 1.4.3, rustc 1.99.1 (58cf8f9c3 2026-10-13).
- Each server runs in isolated directories with authentication enabled and serves the production web build. All three run at once and are measured in rotating order; each number is the median of 3 runs of 5 s after 1 s of warm-up.
- Load comes from `garcon-bench` (`rust/garcon-bench`) on the same machine, so the load generator competes with the servers for CPU. Each client holds one keep-alive connection and sends its next request when the previous response has been read completely.
- CPU per request is the user and system time of the server process tree (front door, original, and their children) during the measured window, divided by the requests completed. "Front door share" is the part of that spent in the Rust process.
